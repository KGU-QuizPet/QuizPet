## 사이드바

- AppController의 창 컨테이너에 FE2 전용 PetStatusPanel 하나를 두고 UI-04·05·06에서 유지한다.
  홈·보스·기록·피드백의 기존 사이드바는 옮기거나 재구성하지 않았다.
- 화면 진입 시 현재 사용자의 실제 펫·레벨·EXP·네 능력치를 읽어 갱신한다.
  사용자 변경 시 이전 표정·문구 순환 상태를 초기화하고 새 펫 값으로 교체한다.
- PetStatusPanel에 CATEGORY(IDLE), LEARNING(FOCUS), QUIZ(FOCUS) 상황을 추가했다.
  기존 상황·공개 API와 PR #88의 6초 말풍선 순환·기본 기울이기·숨김 시 타이머 정지는 유지한다.
- 카테고리·학습에서는 실제 누적 요약, 퀴즈에서는 실제 세션 정답 수·진행 수·분절 진행을 표시한다.
  복습 문항 수를 5개로 제한하지 않는다.
- 조회 실패 시 이전 사용자의 펫 상태를 노출하지 않도록 FE2 사이드바를 숨긴다.
  누적 통계만 조회 실패한 경우 펫은 유지하고 요약만 숨긴다.

## UI-04 실제 데이터

- LearningService의 분야별 카드 목록으로 학습 가능 여부를 결정한다.
  카드가 없으면 준비 중·비활성으로 사전 차단하며 기존 컨트롤러의 진입 검증도 유지한다.
- StatisticsService의 분야별 실제 제출 통계를 표시한다. 제출 0건만 NEW다.
  제출 이력이 있고 정답이 없으면 정답률 0.0%이며 NEW가 아니다.
- 분류 불가 기록·조회 실패는 집계 불가로 표시한다. 가짜 0%나 NEW로 대체하지 않는다.
  전체 분야 통계가 준비된 뒤 일괄 반영하여 일부 분야만 완전한 통계처럼 표시하지 않는다.
- CategoryPanel/CategoryCard는 주입받은 값만 표시하며 저장 파일을 직접 읽지 않는다.

## 남은 디자인 요구 적용

- 학습 제목 기본 44px, 본문 21px. 제목은 작은 폭에서만 축소하고 전체 제목 툴팁을 유지한다.
- RoundCard에 선택적 모서리·그림자 크기를 추가했다. 기존 기본값 20/5는 유지하고
  FE2 대형 학습·문제 카드만 명세의 26/6을 사용한다.
- 넓은 퀴즈 헤더는 220px 진행바·현재 수·종료 버튼을 같은 행에 배치한다.
  좁은 폭에서는 진행바를 다음 행으로 옮긴다. 분야 칩과 유형 칩도 구분한다.
- 학습 ←/→ 이동·Enter 시작, 퀴즈 O/X·1~4 선택·Enter 제출을 연결했다.
  단답형 입력란 Enter도 기존 제출 버튼 경로를 사용한다.
  비활성 버튼, 제출 완료, 피드백 관련 카드의 퀴즈 시작 차단을 우회하지 않는다.
- 미리보기 회귀 수정 조건을 유지한다. 일반·결과 모드의 긴 본문·보기 스크롤도 유지한다.

## 검증 범위

Fe2IntegrationTest는 실제 콘텐츠와 임시 저장 폴더의 실제 서비스 경로를 사용한다.
기존 data/save를 사용하거나 화면에 가짜 통계를 주입하지 않는다.

- 일반 퀴즈 정오답·보상 저장, 피드백과 관련 학습 카드 복귀
- OX·객관식·단답형 키보드 선택/입력·제출
- 세 분야·세 유형의 9문제 오답 생성 → 선택 복습 → 실제 기록·성장 반영
- NEW·0.0%·50.0% 등 실제 통계, 분류 불가 및 손상 기록의 집계 불가 처리
- 콘텐츠가 없는 분야의 사전 비활성화
- 사용자 교체 후 이름·레벨·EXP·능력치·통계 초기화와 원래 사용자 복귀
- PR #88 말풍선 순환 유지·상황 변경·숨김 및 재진입 시 타이머 동작
- 기존 홈·기록·오답노트·보스 화면 이동 및 기존 사이드바 유지
- 1280×800, 1600×900, 1024×768, 800×650에서 320px 사이드바와 콘텐츠 배치

Headless 환경의 타이머 표시 상태 검사는 addNotify/removeNotify로 수행하며,
editable text 입력 검증은 peer가 없는 가상 창의 접근성 오류를 피하도록 분리했다.
물리 키 입력이나 OS 창 캡처를 수행했다는 의미는 아니다.

최종 결과: 운영 81개·테스트 56개 소스의 Java 17 대상 전체 컴파일 통과.
JDK 26.0.2.1에서 `--release 17`을 사용했다. 전체 테스트는 56개 중 55개 통과,
기존 AppLogoTest만 1개 실패했다. 새 회귀 실패는 없다. `git diff --check`도 통과했다.

최종 원격 조회에서도 main은 `551f44c`였다. FE2 개별 구현 때 보류했던
사이드바·실제 통계·콘텐츠 사전 제한은 이번 통합에서 해소했다.

렌더링 PNG와 로그는 Git에서 제외되는 `build/fe2-learning-quiz/`에 있다.
`UI-04-final.png`, `UI-05-final.png`, `UI-06-OX-final.png`,
`UI-06-MULTIPLE_CHOICE-final.png`, `UI-06-SA-final.png`,
`UI-06C-final.png`, `UI-06D-final.png`는 최신 통합 흐름의 콘텐츠 렌더링이다.

## 남은 차이와 별도 항목

- 전역 스타일 변경 금지에 따라 기존 Font.DIALOG와 UiStyle 배경을 유지한다.
  명세의 Jua/Noto Sans KR 폰트·정확한 배경색과는 차이가 있다.
- 학습 본문은 JTextArea 기본 행간이며 명세의 1.7 행간과 동일하지 않다.
- 뒤로 버튼 문구는 기존 API·테스트 계약을 유지한다. 관련 카드에서 피드백으로도 복귀하므로
  항상 분야 선택으로라고 표시하지 않는다.
- 랜덤 도전은 명세의 선택 기능이므로 구현하지 않고 빈 영역을 유지한다.
- FE3 결과·기록·피드백 화면의 전체 재디자인은 이번 범위 밖이다.
- AppLogoTest의 이미지 로딩 상태 assertion 실패는 기존 기준 실패로 남긴다.
  실제 게임 실행에서는 로고가 정상 표시된다는 사용자 확인을 받았다.
  로고 공통 코드·기존 테스트는 변경하지 않는다.
- 800px 등 기준보다 작은 가용 화면에서는 기존 공통 TopBar의 탭이 잘리는 제약이 있다.
  FE2 콘텐츠는 내부 스크롤·진행바 재배치·버튼 줄바꿈으로 접근성을 유지한다.
  다른 화면에도 영향을 주는 TopBar 전역 재설계는 이번 범위에서 하지 않았다.
