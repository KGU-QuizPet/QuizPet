## 2. 핵심 업무 규칙

### 2.1 능력치·분야 매핑

| **분야** | **연결 능력치** | **기본 보상** |
| --- | --- | --- |
| 과학&상식 | 지성(INT) | 최초 정답 +1 |
| 스포츠 | 체력(STR) | 최초 정답 +1 |
| 언어(영어) | 집중력(FOC) | 최초 정답 +1 |
| 역사 | 지혜(WIS) | 최초 정답 +1 |

### 2.2 경험치·정답 처리

| **구분** | **상세 내용** |
| --- | --- |
| 초기 상태 | 레벨 1 / 누적 경험치 0 / 능력치별 10 |
| 첫 정답 보상 | 사용자 기준으로 해당 문제를 처음 맞힌 경우 경험치 +10 및 분야별 능력치 +1 |
| 오답 / 재정답 | 경험치·능력치 추가 보상 없음. 모든 풀이 결과는 기록에 포함 |
| 레벨 계산 | level = 1 + (누적 경험치 ÷ 50의 정수 부분) |
| 경험치 바 | 누적 경험치 % 50을 현재 레벨의 진행 경험치로 표시 |
| 정답률 | 정답 풀이 횟수 ÷ 전체 답안 제출 횟수 × 100; 제출 내역이 없으면 0% |
| 중복 제출 | 한 세션에서 한 문제의 답안 제출은 1회만 가능 |

### 2.3 세션 및 저장 원칙

- 한 퀴즈 세션의 기본 출제 수는 5문제이며, 해당 분야의 문제 수가 적으면 가능한 문제만 출제한다.
- 동일 세션 내 문제 ID는 중복되지 않도록 선정한다. 이미 다른 세션에서 풀었던 문제는 다시 출제될 수 있다.
- 답안 제출 결과는 record.txt에 저장하고, 최초 정답 보상은 pet.txt에도 반영한다. Java 파일 입출력으로 두 파일을 일관되게 관리하며, 오류 발생 시 백업본과 기록 내역으로 정합성을 검사·복구한다.
- 퀴즈 도중 나가면 이미 제출한 답안은 유지되고, 아직 제출하지 않은 문제는 기록하지 않는다.
- 핵심 기능은 오프라인으로 동작하며, 온라인 회원가입이나 실시간 대전은 구현 범위 밖이다.

## 3. 기능별 상세 명세

기능 ID는 PRD와 동일하다. 각 기능의 완료 기준은 개발 종료 전 팀원 간 검증 시 필수 확인 항목으로 사용한다.

### FR-001 사용자 프로필 생성

| **구분** | **상세 내용** |
| --- | --- |
| 우선순위 / 화면 | P0 / UI-01 |
| 실행 조건 | 「새 사용자」 선택 후 닉네임 입력·확인 |
| 사전 조건 | 프로그램이 정상 실행되어 사용자 저장소 접근 가능 |
| 입력 데이터 | nickname: 문자열(앞뒤 공백 제거 후 1~12자) |
| 처리 절차 | 1) 입력 문자열을 정규화한다. 2) 빈 값·길이·중복 여부를 검사한다. 3) 사용자 ID를 생성한다. 4) 사용자 프로필을 저장한다. 5) UI-02로 이동한다. |
| 출력 결과 | 새 사용자 ID 및 닉네임, 생성 완료 안내 |
| 유효성 검증 | 공백만 입력/길이 초과/중복 닉네임은 저장하지 않는다. 닉네임 중복 비교 규칙은 동일 문자열 기준으로 통일한다. |
| 예외 처리 | TXT 파일 저장 실패 시 오류 메시지를 표시하고 입력 화면을 유지한다. 중복 클릭 시 프로필이 두 개 생기지 않아야 한다. |
| 연관 데이터 | User(userId, nickname, createdAt) |
| 완료 기준 | 유효한 닉네임으로 프로필 1개가 생성되며 재실행 후 목록에서 확인된다. |

### FR-002 사용자 프로필 선택

| **구분** | **상세 내용** |
| --- | --- |
| 우선순위 / 화면 | P0 / UI-01 |
| 실행 조건 | 사용자 목록에서 프로필 선택 후 「시작」 |
| 사전 조건 | 저장된 프로필이 1개 이상 존재 |
| 입력 데이터 | userId |
| 처리 절차 | 1) 선택된 userId를 확인한다. 2) 사용자 프로필을 읽는다. 3) 연결된 캐릭터와 학습 기록에 접근한다. 4) 캐릭터가 있으면 UI-03, 없으면 UI-02로 이동한다. |
| 출력 결과 | 선택된 사용자·캐릭터 정보가 반영된 화면 |
| 유효성 검증 | 현재 저장소에 없는 userId를 선택하면 진입을 차단한다. |
| 예외 처리 | 저장된 사용자가 없으면 생성 안내를 보인다. 사용자 로드 실패 시 경고하고 시작 화면을 유지한다. |
| 연관 데이터 | User, Pet, PetStats, LearningRecord |
| 완료 기준 | 프로필 A와 B의 캐릭터·학습 기록이 서로 섞이지 않고 독립적으로 표시된다. |

### FR-003 캐릭터 생성

| **구분** | **상세 내용** |
| --- | --- |
| 우선순위 / 화면 | P0 / UI-02 |
| 실행 조건 | 캐릭터 이름 입력 후 「생성」 |
| 사전 조건 | 선택된 사용자가 존재하고 해당 사용자의 캐릭터가 없음 |
| 입력 데이터 | userId, petName: 공백 제외 1~12자, spriteKey: 외형 2~3종 중 1개 |
| 처리 절차 | 1) 이름을 검증한다. 2) 준비된 외형 2~3종 중 하나를 선택한다. 3) 레벨 1·누적 XP 0·능력치 4종 각 10을 설정한다. 4) Pet 및 PetStats를 저장하고 UI-03을 연다. |
| 출력 결과 | 새 캐릭터와 초기 능력치가 표시된 메인 화면 |
| 유효성 검증 | 빈 이름·길이 초과 입력과 정의되지 않은 spriteKey를 거절한다. 사용자당 캐릭터는 1개만 허용한다. |
| 예외 처리 | 생성 중 파일 쓰기 오류 발생 시 저장을 취소한다. 캐릭터만 저장되고 능력치가 누락되는 부분 저장을 방지한다. |
| 연관 데이터 | Pet(petId, userId, name, spriteKey, totalXp), PetStats(strength, intelligence, focus, wisdom); pet.txt에는 한 줄로 통합 저장, level은 XP에서 계산 |
| 완료 기준 | 외형 2~3종 중 선택한 모습과 초기 능력치가 저장되며 중복 생성은 차단된다. |

### FR-004 캐릭터 능력치 표시·갱신

| **구분** | **상세 내용** |
| --- | --- |
| 우선순위 / 화면 | P0 / UI-03, UI-07 |
| 실행 조건 | 메인 화면 진입 또는 퀴즈 보상 확정 |
| 사전 조건 | 캐릭터가 생성되어 있고 분야-능력치 매핑이 설정됨 |
| 입력 데이터 | petId, categoryId, rewardStatAmount(0 또는 1) |
| 처리 절차 | 1) 저장된 4개 능력치를 조회한다. 2) 퀴즈 최초 정답인 경우 분야에 대응하는 능력치만 1 증가시킨다. 3) UI에 갱신값을 표시한다. |
| 출력 결과 | STR·INT·FOC·WIS 값과 변경량 |
| 유효성 검증 | 능력치는 음수가 될 수 없다. 정답이 아니거나 이미 보상을 받은 문제는 증가량 0으로 처리한다. |
| 예외 처리 | 데이터 누락 시 초기값 자동 추정으로 보상을 지급하지 말고 경고·복구 처리를 한다. |
| 연관 데이터 | PetStats, Category, LearningRecord |
| 완료 기준 | 과학&상식 최초 정답 시 INT만 1 증가하고 다른 능력치는 변하지 않는다. |

### FR-005 경험치·레벨업 처리

| **구분** | **상세 내용** |
| --- | --- |
| 우선순위 / 화면 | P0 / UI-03, UI-07 |
| 실행 조건 | 정답 제출 및 보상 확정 시 |
| 사전 조건 | 정답 판별 완료, 중복 보상 지급 여부 확인 완료 |
| 입력 데이터 | petId, questionId, isCorrect, alreadyRewarded |
| 처리 절차 | 1) 최초 정답인지 판별한다. 2) 해당하면 누적 XP +10 및 분야별 능력치 +1을 적용한다. 3) 레벨 = 1 + floor(totalXp/50)으로 계산한다. 4) 변경 내용을 저장한다. 5) 결과 화면에 변화량을 전달한다. |
| 출력 결과 | 획득 XP, 능력치 증가량, 변경 전후 레벨·경험치 |
| 유효성 검증 | 오답·재정답의 보상은 0이다. XP는 음수가 될 수 없다. |
| 예외 처리 | 저장 실패 시 부분 보상 지급이 발생하지 않도록 풀이 기록 및 캐릭터 갱신을 함께 복구하도록 처리한다. |
| 연관 데이터 | Pet, PetStats, LearningRecord |
| 완료 기준 | 누적 XP 40인 캐릭터의 최초 정답 한 번은 XP 50, 레벨 2, 진행 경험치 0/50으로 표시된다. |

### FR-006 학습 분야 선택

| **구분** | **상세 내용** |
| --- | --- |
| 우선순위 / 화면 | P0 / UI-04 |
| 실행 조건 | 메인 화면의 「학습하기」 버튼 |
| 사전 조건 | 사용자 프로필 및 캐릭터가 로드되어 있음 |
| 입력 데이터 | categoryId: SCIENCE(과학&상식), SPORTS(스포츠), HISTORY(역사), LANGUAGE\[언어(영어)\] 중 1개 |
| 처리 절차 | 1) 학습 분야 목록을 가져온다. 2) 분야별 이름·설명·능력치 연결 정보를 보여준다. 3) 사용자가 선택하면 categoryId를 유지한 채 UI-05로 이동한다. |
| 출력 결과 | 선택 분야의 학습 콘텐츠 목록 |
| 유효성 검증 | 정의되지 않은 categoryId는 허용하지 않는다. |
| 예외 처리 | 관련 학습 콘텐츠가 없는 분야는 비활성화하고 안내한다. |
| 연관 데이터 | Category(categoryId, name, statType) |
| 완료 기준 | 스포츠 선택 시 스포츠 카드만 표시되고 이후 퀴즈 보상은 STR에 연결된다. |

### FR-007 학습 콘텐츠 조회

| **구분** | **상세 내용** |
| --- | --- |
| 우선순위 / 화면 | P0 / UI-05 |
| 실행 조건 | 학습 분야 선택 / 이전·다음 카드 이동 |
| 사전 조건 | 정상적인 categoryId가 전달됨 |
| 입력 데이터 | categoryId, contentIndex |
| 처리 절차 | 1) 분야에 해당하는 학습 자료를 불러온다. 2) 제목·설명·난이도·키워드를 카드로 표시한다. 3) 이전/다음 버튼으로 인덱스를 이동한다. 4) 연계 문제가 있으면 「퀴즈 시작」을 활성화한다. |
| 출력 결과 | 학습 카드 및 현재/전체 카드 진행 상태 |
| 유효성 검증 | 인덱스는 0부터 마지막 카드 범위만 허용한다. |

## 4. 데이터 입력·저장 및 오류 처리 규칙

### 4.1 데이터 구분

| --- | --- | --- |

### 4.2 필드 및 제약

| **데이터** | **핵심 필드** | **제약 및 참고** |
| --- | --- | --- |
| User / user.txt | userId, nickname, createdAt | 닉네임 1~12자, 중복 불가, \_ 입력 제한 |
| Pet / pet.txt | petId, userId, name, spriteKey, totalXp, STR, INT, FOC, WIS | Pet와 PetStats를 한 줄 저장; level = 1 + totalXp / 50 |
| Category / category.txt | categoryId, name, statType, description | 과학&상식→INT, 스포츠→STR, 역사→WIS, 언어(영어)→FOC |
| LearningContent / content.txt | contentId, categoryId, order, difficulty, title, tags, description | 학습 카드당 2줄; 제목·태그와 본문 |
| Question / question.txt | questionId, categoryId, contentId, type, answer, options, prompt, explanation | OX/객관식; 문제당 3줄, 객관식 보기 4개 |
| LearningRecord / record.txt | recordId, userId, questionId, sessionId, answer, isCorrect, earnedXp, answeredAt | 제출마다 1줄 추가; 최초 정답만 XP +10 |
| BattleRecord / battle.txt (P2) | battleId, petIdA, petIdB, winnerPetId, turns, playedAt | 결투 기능 구현 시에만 기록 |

모든 TXT 파일은 UTF-8로 관리한다. category/content/question은 data/content, user/pet/record/battle은 data/save에 둔다. 긴 문제·해설은 다음 줄에 저장하며, 로딩 후 Java Question 하위 클래스로 변환한다. 파일 필드 순서는 별도 데이터 구성 문서를 따른다.

### 7.1 MVP 완료 조건

- 학습 분야 4개, 학습 카드 40개 이상, OX·4지선다 퀴즈 80문제 이상 준비
- 사용자·캐릭터 생성/선택/상태 조회 기능 정상 작동
- 풀이 기록과 보상 계산이 일관되며 동일 문제 중복 경험치 지급을 방지
- 세션 종료·재실행 후에도 사용자/캐릭터/학습 기록 복원
- 필수 테스트 TC-01~16 통과 및 팀원 간 통합 시연 완료

본 명세서는 개발 착수 기준 문서다. 성장 수치 및 UI 세부 문구는 테스트 결과에 따라 합의 후 변경할 수 있으며, 변경 시 PRD·화면 설계서와 함께 버전을 갱신한다.
